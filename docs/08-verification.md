# 실행 검증 기록

> 아래 알림 검증 내용은 제거 전 구현의 과거 기록이다. 현재 알림 코드·화면·작업 API·cron은 제거되었으며 신규 Spring Batch는 아직 구현하지 않았다. 현재 변경 검증 결과는 문서 마지막에 기록한다.

## 최신: 일별 가계부 웹앱 개편 (2026-09-22)

가계부 메인을 일별 표와 네 가지 요약으로 재구성했다. 날짜 선택/더블클릭/버튼 → 날짜별 모달 → 지출 조회·등록·수정·카테고리 추가 흐름을 실제 Oracle 앱에서 검증했다. 월 예산은 별도 모달이며 가계부·카테고리·알림은 공통 헤더와 폭을 사용한다. 연도별 테마 교체 방법은 [09 테마 관리](09-theme.md)에 기록했다.

| 검증 | 결과 |
|---|---|
| Java/JUnit·MockMvc | 30개 통과, 기존 MVC 로그인 리다이렉트 회귀 포함 |
| JavaScript/Node | 18개 통과, 금액 정밀도·응답 검증·타임아웃·월 전환 상태 포함 |
| 실제 Oracle HTTP | 25개 통과, 금액/입력 경계·회원 격리·CSRF·분류 활성 상태·삭제 후 조회 |
| Edge 기본 화면 흐름 | 17개 통과, 모달·초안 유지·키보드·모바일390/320px·윤년 |
| Edge 예외 상황 | 9개 통과, 한글 헤더·401/403·저장중 닫기 차단·저장후 조회실패 복구·월 전환 지연·테마 교체 |
| 색상 대비 | 14개 조합 기준 통과, 본문4.5:1/컨트롤3:1 이상 |
| 최종 WAR/Docker | 빌드 성공, 앱/Oracle 실행, `/actuator/health` UP |

테스트를 먼저 실패시킨 뒤 고친 항목: 기존 화면에 날짜 모달 없음, 새 API 계약, MVC 로그인 리다이렉트 영향, 응답 본문 수신 중 타임아웃 누락, 느린 월 조회와 열린 모달의 월 혼동, 공통 JSP 조각의 한글 인코딩 누락. 최종 스크린샷에서 상단 메뉴 한글 표시를 직접 확인했다.

검증 범위와 한계:

- 브라우저는 headless Edge의 실제 렌더링 엔진을 사용했다. 모바일은390/320px 뷰포트 시뮬레이션이며 실물 스마트폰 검증은 아니다.
- 삭제 확인 취소는 UI에서 확인했고, 실제 삭제와 집계 갱신은 인증 HTTP 요청과 재조회로 확인했다.
- 401/403 및 저장 후 조회 실패는 브라우저 응답을 제어해 화면 처리를 검증했다. 실제 서버의 비인증/CSRF 응답도 별도 HTTP로 검증했다.
- 테마 진입 파일의 import 경로를 브라우저 응답에서 바꿔 다른 팔레트가 적용되는지 확인한 후2027로 복원했다. 임시 테마를 운영 파일에 남기지 않았다.
- 연도 자동 전환과 모바일 길게 누르기는 구현 범위에서 제외했다.
- 요구사항·코드 품질·보안·맥락·QA의 다섯 검토가 통과했다. 최종 한글 수정은 이후 실제 브라우저 재검증으로 확인했다.

정리: 이번 QA 전용 회원ID61·81의 이메일을 먼저 대조한 후 두 회원과 해당 알림·예산·지출·개인 분류만 트랜잭션으로 삭제했다. 다른 회원 수가 그대로임을 확인했다. 가상 데이터는 별도 백업 없이 제거했다. 브라우저와 임시 실행 도구는 종료/제거했고, 앱과 Oracle 컨테이너는 사용자 확인을 위해 실행 상태로 유지한다. 사용자 데이터·DB 볼륨은 보존했다. 커밋/푸시는 하지 않았다.

증거: `.omo/evidence/ledger-ux/`의 `browser-results.txt`, `browser-edge-results.txt`, `http-results.txt`, `final-main.png`, `day-dialog-390.png`, `cleanup.txt`, `review.md`. Java 결과는 `build/reports/tests/test/index.html`. 자동 재검증: `gradlew test bootWar`, `node --test src/test/js/*.test.mjs`.

## 실제 브라우저 확인
Edge/Playwright로 다음을 확인했다. 단순 MockMvc가 아닌 Oracle에 연결된 실행 WAR를 사용했다.

- 로그인·회원가입 JSP와 CSS 렌더링.
- 자체 회원가입, 대문자 이메일 정규화 로그인, 초기 예산 미설정 안내.
- 월 예산 300,000원 저장.
- 지출 12,000원 등록, 메모 내 script 문자열 이스케이프, 15,000원으로 수정.
- 일일 알림 생성, 동일 날짜 재실행 시 생성 0건.
- 세션이 있어도 전용 작업 토큰 누락은401.
- 알림 조회/읽음 처리.
- 1440px 데스크톱과390px 모바일 화면 확인, 페이지 가로 넘침 없음(표 내부 스크롤).
- 지출 삭제 후 목록·합계 갱신, 삭제한 상세404.
- 로그아웃 후 보호화면은 로그인으로 이동.

첫 화면 알림 모델 누락은 실패하는 회귀 테스트를 먼저 추가한 뒤 수정했다. 최종 컨테이너의 첫 화면 알림·카테고리 UI 재검증 결과는 아래 최종 확인에 기록한다.

## 실제 Oracle HTTP 경계 검증
서로 다른 회원 2명을 가입·로그인시켜 검증했다.

1. 이메일·카테고리의 정규화 중복 거부.
2. 0/음수/소수/14자리 초과 금액, 잘못된 월·날짜, 201자 메모 거부.
3. 타인 카테고리 사용, 공용 카테고리 변경, 타인 지출 조회/수정/삭제 거부.
4. 비활성 카테고리는 새 지출 불가, 기존 지출 수정은 유지 가능.
5. 로그인 세션으로 CSRF 생략 시403.
6. Oracle에서 작업4개 동시 요청 시 신규 알림 합계1건.
7. 예산 없는 회원 알림 생략, 타인 알림 읽음 처리404.

## 알려진 환경 제약
- Windows에서1521·1522 바인딩이 차단되어 호스트11521 사용. Toad도11521로 접속.
- Flyway11.7.2는 Oracle23.26에 대해 지원 검증 범위 경고를 출력한다. 실제 V1 DDL·Hibernate 검증·CRUD는 통과했다. 운영 DB/도구 버전은 배포 전 호환 매트릭스 재검증 필요.
- Toad 프로그램 자체를 조작한 검증은 하지 않았다. 동일 JDBC 서비스·스키마 연결과 실제 DB 테이블을 확인했다.
- 실제 Linux 호스트 crontab의 자정 예약 설치는 배포 단계에서 한다. 이번에는 동일 스크립트를 Linux에서 직접 호출하고 중복/동시 실행을 검증했다.
- GitLab 원격, Jenkins, SonarQube, AWS, Jennifer, Scouter는 설계 문서 범위이며 외부 서비스에 연결하지 않았다.

## 최종 확인 및 정리
- 최종 Linux 컨테이너 브라우저 검증 15개 통과. 첫 화면의 일일 알림/읽음 상태, 카테고리 추가·이름 변경·비활성화까지 확인했다.
- 별도 실제 Oracle HTTP 경계 검증 15개 통과. 비인증/CSRF/토큰 경계의 독립 검토도 통과했다.
- 테스트 전용 회원 6명의 ID와 이메일을 먼저 대조한 후 해당 회원의 알림·지출·예산·개인 카테고리·계정을 트랜잭션으로 삭제했다. 회원/예산/지출/알림은 0건, 공용 카테고리는 5건으로 확인했다. 사용자 계정이나 기존 ETFGeniusGuide 데이터는 삭제하지 않았다.
- Windows WAR 프로세스, 임시 Linux 작업 컨테이너, 테스트 브라우저는 종료했다. 최종 확인 후 앱/Oracle 컨테이너도 `docker compose --profile app stop app oracle`로 종료했다. 이미지와 DB 볼륨은 보존했다. 다시 사용하려면 `docker compose --profile app up -d`로 시작한다.
- 로컬 Git 저장소 main 브랜치 초기화. .env가 무시되며 추적 파일이 아님을 확인했다. 아직 커밋과 원격 푸시는 하지 않았다.
- Java LSP(jdtls)는 설치되지 않아 LSP 진단을 수행하지 못했다. 이를 무오류로 간주하지 않으며, 대체 검증으로 Java 컴파일·24개 테스트·실제 WAR/Oracle 기동을 확인했다.
- 품질·보안·원본 이관 맥락·독립 HTTP 검토는 통과. 요구사항 검토에서 발견한 첫 화면 알림 누락은 회귀 테스트를 실패→성공으로 확인하고 실제 브라우저로 재검증했다. 수정 후 요구사항 재검토도 통과하여 다섯 검토 모두 통과했다.
- 검증용 임시 실행 스크립트와 디버그 메모는 제거했다. 프로젝트 자동 테스트와 검증 스크린샷은 보존했다. 삭제한 가상 계정은 테스트 전용이며 별도 백업은 만들지 않았다.

## 재현과 증거 위치
자동 테스트: `gradlew test bootWar`, 결과 `build/reports/tests/test/index.html`.
Docker: `docker compose --profile app up -d` 후 `/actuator/health`의 `{"status":"UP"}` 확인.
수동 시나리오: 새 계정 가입→로그인→월 예산300,000원→1일 지출12,000원→15,000원으로 수정→알림 작업→읽음→지출 삭제→카테고리 추가/수정/비활성→로그아웃.
스크린샷은 로컬 `.omo/evidence/login.png`, `budget-desktop.png`, `budget-mobile.png`, `categories.png`에 보관했다. 이 진단 산출물은 Git 제외 대상이며 테스트용 가상 데이터만 포함한다.


## 기존 알림 제거 검증 (2026-10-11)
- Java 테스트 26개, JS 테스트 18개 통과. bootWar 성공.
- 알림 조회/읽음 경로 제거(404), 대시보드 dailyNotice 모델 제거, 내부 작업 CSRF/인증 예외 제거를 회귀 테스트로 확인.
- Docker 앱 정상 상태 UP, 실제 기존 작업 POST는 403으로 차단. V1 마이그레이션은 변경하지 않았고 DB 삭제 작업 없음.
- Windows 예약 포트 범위 8037~8136에 8080이 포함되어 이번 Docker 실행은 APP_PORT=18080으로 대체. .env는 변경하지 않음.
- 브라우저 육안 검증은 연결 가능한 브라우저가 없어 미수행. 독립 검토 일부는 도구 사용 한도 때문에 완료하지 못했으며 전체 검토 통과를 주장하지 않음.


## 역할별 패키지 정리 검증 (2026-10-12)
- 운영 클래스 24개와 테스트 7개를 api/controller, api/service, domain, common/exception 구조로 이동. package/import 외 업무 동작 변경 없음.
- clean test bootWar 성공: Java 26개 통과. JS 18개 통과. WAR의 이전 budget/member/notification 패키지 클래스 없음.
- Docker 8080 배포 후 health UP, 로그인 JSP 정상 렌더링, 비인증 가계부 접근 302 확인. DB 마이그레이션 변경 없음.
- Java LSP는 jdtls 미설치로 미실행. 독립 검토는 사용 한도로 완료하지 못했으며 브라우저 전체 사용자 흐름 검증은 미수행. 컴파일·통합 테스트·HTTP 확인으로 검증 범위를 한정한다.
